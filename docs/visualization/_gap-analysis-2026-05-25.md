## Method

Full-page screenshot captured at 1440×900 using Playwright directly against the live Dash app (port 8057). The dashboard is a single continuous scroll, not a true multi-page router — all five "pages" (przeglad, wydatki, dlug, ue, prognozy) are anchor-linked sections within one page. Per-section screenshots cropped from the full-page capture at y-boundaries derived from DOM inspection. Screenshots saved at `/tmp/pf-screenshots/` (session-scoped; not committed). Each section evaluated against every applicable rubric dimension. YAML visual configs read alongside screenshots to verify intent vs rendering for items not fully legible at thumbnail scale.

## Headline

The dashboard is structurally coherent and domain-correct: SGP threshold lines are present on every fiscal chart, Poland is highlighted in cross-country comparisons, and charts are sorted by value not alphabet — all of which are non-trivial domain capabilities that many practitioner dashboards lack. The failure pattern is not structural incompetence but design immaturity: the dashboard is a functional analytical skeleton without a visual language. Roughly 40% of rubric dimensions pass, 35% are partial, and 25% fail outright across the five sections. The most common failure modes are: (1) uniform blue palette with no grey-primary / accent-secondary discipline, (2) multi-line legends where direct endpoint labelling should be used, (3) no section-level hierarchy visible — all five sections look identical in weight and style, (4) no chart-level annotations for structural breaks (COVID 2020 spike is visible but unlabelled on multiple charts), (5) no paired precision tables. The most surprising finding is that the `prognozy` section is the strongest — it correctly dashes the forecast segment and has two reference lines — while `wydatki` is the weakest due to multi-colour legend abuse on the COFOG trend chart.

## Cross-page patterns

**Dimensions that fail or partially fail on every applicable page:**

- **Dimension 3 (chart + precision table)** — FAIL on all 5 pages. No section in the dashboard provides a paired data table. Every chart requires hover interaction to retrieve any precise value. This is the single most consistent gap.
- **Dimension 6 (direct labelling)** — FAIL or PARTIAL on every page with multi-series charts. Specifically the COFOG trend (wydatki) uses a top legend box for 4 series where endpoint labels are clearly feasible.
- **Dimension 8 (grey primary / accent)** — FAIL or PARTIAL on przeglad, wydatki, dlug, prognozy. Only the `ue` section correctly applies grey-for-context / accent-for-signal. The remaining 4 sections use uniform blue for all data series, treating historical and current data at equal visual weight.
- **Dimension 12 (delta taxonomy)** — FAIL or N/A on all pages. KPI cards on przeglad show no YoY delta. The interest-cost doubling trend on dlug has no callout. The forecast breach on prognozy has no callout.
- **Dimension 17 (narrative / sequential zoom)** — FAIL or PARTIAL on all 5 pages. The dashboard presents charts without guiding text or annotations that would turn data into an argument. The analytical story is implied, not constructed.
- **Dimension 21 (structural breaks annotated)** — FAIL on przeglad, wydatki, dlug; PARTIAL on prognozy; N/A on ue. COVID 2020 is the most visible structural break across 6 charts and is annotated on zero of them.
- **Dimension 9 (blue/orange, not red/green)** — PARTIAL on przeglad: KPI badge colours use red for deficit (warning) and green for compliant debt — stoplight semantics that fail deuteranopia.

**Page-level strength ranking:**

2. **Second: przeglad** — Most complete structural layout (KPIs + trends + EU bar); reference lines on all applicable charts; F-scan layout correct. Weakest on deltas and structural break annotation.

## Phase C scoping implications

Ordered by number of failures closed per engine capability:

1. **Inline chart annotations primitive** — Closes dimension 21 failures on przeglad/wydatki/dlug/prognozy (4+ pages) and partially resolves dimension 17.
   Needed: `annotations` list in YAML visual config, each with `{ x: year, text: "label", direction: above|below }`, rendered as Plotly `add_annotation()` calls. Without this, authors have no declarative way to mark structural breaks.

2. **Delta component on KPI cards** — Closes dimension 12 failures on przeglad and prognozy.
   Needed: `delta` block in card YAML with `{ vs: prior_year | target, format: icon-first | textual }`, rendered as a ΔΔ indicator below the headline value. Currently cards show static current-value only.

3. **Direct endpoint labelling for line charts** — Closes dimension 6 failures on wydatki/prognozy.
   Needed: `label_endpoints: true` option in line visual config; dbr renders the final data point with a text annotation matching the series name, eliminating the need for a top legend box on single-series and few-series charts.

4. **Precision table as optional companion** — Closes dimension 3 failures on all 5 pages.
   Needed: `table: true` or `table: { rows: 5 }` option on any visual; dbr renders a `dash_table.DataTable` beneath the chart with the underlying query data, paginated if long. This is the highest-frequency failure and architecturally simple.

5. **Grey-primary colour discipline in multi-series lines** — Closes dimension 8 failures on wydatki/dlug/prognozy.
   Needed: when `color` dimension is not present (single series), the line renders in the accent colour (correct). When `color` dimension is present (multi-series), dbr should map the "dominant" or "selected" category to accent and all others to a grey ramp — requiring a `highlight` option analogous to the bar chart, or a `palette: grey-accent` option in visual config.

6. **Narrative / section lead-in text** — Partially closes dimension 17 failures on all pages.
   Needed: `prose` or `narrative` block in `page.yml` or in individual `row` items that renders a Markdown paragraph above the chart row — giving authors a declarative way to write the analytical sentence that bridges two charts. Without this, authors have no first-class text slot.

7. **Badge colour semantics (blue/orange, not red/green)** — Closes dimension 9 PARTIAL on przeglad.
   Needed: KPI card `threshold.rule` logic should emit `state: over | under | compliant` and map to the design system's semantic colours (orange for breach, blue for safe) rather than red/green CSS classes.

8. **Dual-year grouped bar variant** — Closes dimension 13 FAIL on ue.
   Needed: `dual_year: true` option on bar visuals, rendering prior-year bars in slate grey alongside current-year accent bars — enabling YoY cross-country comparison without a time slider.

9. **Section sub-title / chart title primitive** — Partially closes dimension 1 failures on wydatki/dlug/ue.
   Needed: `title` field per `row` or per `visual` that renders a visible H3-level label above the chart, enabling readers to distinguish "deficit snapshot" from "debt trend" within the same section without reading chart axes.

10. **Colorblind palette enforcement** — Closes dimension 11 PARTIAL on wydatki; prevents future red/green regressions.
    Needed: dbr should restrict the design system token set to a colorblind-safe palette by default (ruling out the red/green for badge states); design-token audit before Phase C ships any new colour.

## Items the rubric flagged but the dashboard already handles well

- **Dimension 4 (chart type correctness)** — All chart types in the dashboard are correct FT Visual Vocabulary choices: line for time series, sorted horizontal bar for cross-section rankings, diverging bar for balance deviations. No pies, no stacked bars with multiple non-baseline series, no 3D.
- **Dimension 5 (reference lines)** — Reference lines are present on every chart where they are analytically relevant. SGP -3% appears on balance trends and cross-country deficit bars; Maastricht 60% appears on debt trends and cross-country debt bars; the equilibrium line appears on projection charts. This is the strongest analytical feature in the current build.
- **Dimension 7 (zero baseline)** — All bar charts use correct zero baselines. No truncation defect.
- **Dimension 14 (whitespace, no eyeball attack)** — Module density is low throughout. No section exceeds 2 charts. Margins are generous. The dashboard does not try to show everything simultaneously.
- **Dimension 18 (anti-patterns)** — The forbidden list (gauges, 3D, pie/donut, dark background, rainbow gradient) is entirely absent. This reflects correct declarative constraints in the YAML visual schema.
- **Dimension 19 (SGP thresholds mandatory)** — See dimension 5 — the domain extension is fully implemented.
- **Dimension 20 (Poland highlighted)** — Correct on both ue section charts with grey/azure contrast; sort-by-value so Poland's position in the league table is immediately legible.
- **Dimension 2 (F/Z scan layout)** — Within each section, the most important visual is first. Across the page, the overall section order follows a logical analytical arc (snapshot → expenditure → debt → EU context → forecast).
