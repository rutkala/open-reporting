## 1. Reproducible Research Standards

### 1.1 The Reproducibility Contract

Every research product (notebook, model, analysis) must satisfy the reproducibility contract:

| Requirement | What it means |
|------------|--------------|
| **Data lineage** | Every dataset used is named with source, version, access date, and exact query or file path |
| **Code runs end-to-end** | A fresh environment with the specified dependencies can reproduce all outputs from raw data to final tables/figures |
| **Random seeds fixed** | Any stochastic process (bootstrapping, Monte Carlo, random splits) uses a fixed, documented seed |
| **Software versions pinned** | Python version, key package versions (pandas, statsmodels, linearmodels, numpy) recorded |
| **Output matches code** | Tables and figures in the notebook are generated by the code cells, not pasted or manually edited |

### 1.2 Notebook Structure

Standard Jupyter notebook structure for research:

```
1. Title and research question
2. Data section: sources, loading, cleaning (with provenance)
3. Descriptive statistics: summary tables, distributions
4. Methodology: model specification, assumptions stated explicitly
5. Results: coefficient tables, diagnostic tests
6. Robustness checks: alternative specifications, subsamples
7. Interpretation: what the coefficients mean, limitations
8. Reproducibility note: environment, versions, seeds
```

### 1.3 The Robustness Imperative

Brode et al. (Nature, 2026) — the largest systematic reproducibility study in economics to date — found that a significant fraction of published results fail computational reproducibility checks. The lesson: **every result must be tested against alternative specifications before being trusted.**

**Minimum robustness checks for any causal claim:**
1. **Alternative controls** — add/remove plausible confounders; does the coefficient change materially?
2. **Alternative functional forms** — linear vs. log vs. quadratic; does the sign and significance hold?
3. **Alternative sample** — exclude outliers, restrict to subsample, extend time window
4. **Alternative standard errors** — robust, clustered, HAC; does inference change?

If a result disappears under any of these checks, it is not robust. Report this honestly.

## 2. Model-Specific Standards

### 2.1 Ordinary Least Squares (OLS)

**When to use:** Baseline estimation, descriptive relationships, linear conditional expectation functions.

**Assumptions that must be checked:**

| Assumption | How to check | Failure remedy |
|-----------|-------------|----------------|
| **Linearity** | Residual vs. fitted plot; Ramsey RESET test | Transform variables, add polynomial terms, use nonparametric methods |
| **Homoskedasticity** | Breusch-Pagan test, White test | Use heteroskedasticity-robust standard errors (HC1/HC3) |
| **No perfect multicollinearity** | VIF > 10 signals concern | Remove redundant variables, use ridge/lasso, combine variables |
| **No autocorrelation** | Durbin-Watson test, Breusch-Godfrey (time series) | Use HAC (Newey-West) standard errors, GLS |
| **Normality of residuals** | Jarque-Bera test, Q-Q plot (for inference, not estimation) | Bootstrap standard errors, transform dependent variable |
| **Exogeneity** | Cannot be tested directly — must be argued from theory | IV approach if endogeneity is plausible |

**Rules:**
- **Always report robust standard errors** — heteroskedasticity is the norm, not the exception, in economic data. HC3 is preferred for small samples.
- **Report R-squared and adjusted R-squared** — but do not over-interpret. A high R-squared does not mean the model is correct; a low R-squared does not mean it is useless.
- **Report the number of observations** — always. A coefficient without an N is uninterpretable.
- **Cluster standard errors** when data has a group structure (regions, firms, individuals observed over time). Cluster at the level of treatment assignment or the highest level of correlation.

### 2.2 Instrumental Variables (IV)

**When to use:** When the treatment variable is endogenous (correlated with the error term) and a valid instrument exists.

**Instrument validity requirements:**

| Criterion | What it means | How to assess |
|-----------|--------------|--------------|
| **Relevance** | Instrument is correlated with the endogenous variable | First-stage F-statistic > 10 (Stock-Yogo critical value); weak instruments bias IV estimates toward OLS |
| **Exclusion** | Instrument affects the outcome only through the treatment | Cannot be tested statistically — must be argued from theory and institutional knowledge |
| **Exogeneity** | Instrument is uncorrelated with the error term | Cannot be tested directly — overidentification tests (Sargan, Hansen J) provide partial evidence when multiple instruments exist |

**Lal et al. (2024) practical advice from 67 replicated IV studies:**
- First-stage F-statistics below 10 are a red flag — weak instruments produce biased estimates with misleadingly narrow confidence intervals
- IV estimates are often much larger than OLS — this is expected (LATE vs. ATE) but requires careful interpretation
- Always report both OLS and IV estimates side by side
- Always report the first-stage results, not just the second stage
- Overidentification tests are necessary but not sufficient — they cannot detect violations of the exclusion restriction

**Rules:**
- **Never use IV without reporting the first stage** — the reader must see the instrument's predictive power.
- **Never claim causality from IV without discussing the exclusion restriction** — this is the weakest link and must be addressed honestly.
- **Report the LATE interpretation** — IV estimates the Local Average Treatment Effect for compliers, not the ATE for the full population.

### 2.3 Difference-in-Differences (DiD)

**When to use:** When a policy or intervention affects one group (treatment) but not another (control), and pre/post data exists for both.

**Assumptions that must be checked:**

| Assumption | What it means | How to check |
|-----------|--------------|--------------|
| **Parallel trends** | In the absence of treatment, treatment and control groups would have followed the same trend | Plot pre-treatment trends; event-study coefficients for pre-periods should be statistically indistinguishable from zero |
| **No anticipation** | Units do not change behaviour before the treatment takes effect | Check for pre-treatment effects; if present, treatment date may be earlier than assumed |
| **No compositional change** | The composition of treatment and control groups does not change systematically around the treatment | Check sample composition before and after; attrition analysis |
| **Stable unit treatment value (SUTVA)** | One unit's treatment does not affect another unit's outcome | Argue from context; check for spillovers |

**Modern DiD considerations (post-2020 literature):**
- **Staggered adoption** — when units receive treatment at different times, the traditional two-way fixed effects (TWFE) estimator is biased. Use Callaway & Sant'Anna (2021), Sun & Abraham (2021), or Goodman-Bacon decomposition.
- **Event-study design** — always plot dynamic effects: leads (pre-treatment) and lags (post-treatment). This is the single most informative diagnostic for DiD validity.
- **Clustering** — cluster standard errors at the treatment level, not at the observation level.

**Rules:**
- **Always show the parallel trends plot** — this is non-negotiable for DiD.
- **Always use modern estimators for staggered adoption** — TWFE is biased when treatment effects are heterogeneous and timing varies.
- **Report the number of treated and control units** — small treatment groups produce imprecise estimates.

### 2.4 Synthetic Control

**When to use:** When a single unit (country, region) receives a treatment and a weighted combination of untreated units can construct a plausible counterfactual.

**Assumptions that must be checked:**

| Assumption | What it means | How to check |
|-----------|--------------|--------------|
| **Donor pool quality** | Untreated units are plausible comparators | Pre-treatment fit: the synthetic control should track the treated unit closely before intervention |
| **No anticipation** | The treated unit does not change behaviour in anticipation | Check pre-treatment divergence |
| **No spillovers** | The treatment does not affect donor pool units | Argue from context; exclude units likely to be affected |
| **No post-treatment intervention** | No other major policy change coincides with the treatment | Document the policy context; acknowledge confounding events |

**Rules:**
- **Always show the pre-treatment fit** — a poor pre-treatment fit invalidates the counterfactual.
- **Always run placebo tests** — apply the method to untreated units; the treated unit's effect should be an outlier.
- **Report the donor weights** — transparency about which units contribute to the synthetic control is essential.

## 3. Standard Errors & Inference

### 3.1 Choosing the Right Standard Errors

| Data structure | Standard error type | When to use |
|---------------|-------------------|-------------|
| Cross-sectional, independent | OLS (default) | Rarely appropriate in practice |
| Cross-sectional, heteroskedastic | Robust (HC1/HC3) | Default for cross-sectional data |
| Panel, individual-level | Clustered by individual | Panel data with repeated observations |
| Panel, group-level treatment | Clustered by treatment group | DiD, policy evaluation |
| Time series | HAC (Newey-West) | Autocorrelation present |
| Spatial | Conley / spatial HAC | Geographic correlation |
| Multi-way | Two-way clustered | When correlation exists along two dimensions |

**Rule:** When in doubt, cluster. Clustering is always conservative; non-clustered SEs are anti-conservative when correlation exists.

### 3.2 Multiple Testing

When running multiple hypothesis tests, the probability of at least one false positive increases. For research products that test many hypotheses:

- **Bonferroni correction** — divide significance level by the number of tests. Conservative but simple.
- **Benjamini-Hochberg procedure** — controls the false discovery rate. Less conservative, more power.
- **Pre-registration** — declare the primary hypothesis before seeing the data. Exploratory analyses are labelled as such.

**Rule:** If a research product reports 20+ coefficients and highlights the 2 that are significant at p < 0.05, flag this as potential p-hacking.

## 4. Polish Public Data Quirks

### 4.1 GUS Data Revisions

Statistics Poland (GUS) follows a formal revision policy. Key points:

- **Preliminary estimates** are published first, followed by revised estimates. The revision magnitude varies by series.
- **National accounts** undergo major revisions when ESA methodology changes (ESA 1995 → ESA 2010 → ESA 2025). The 2024 revision covered 1995–2022.
- **Labour market data** — BAEL (LFS) methodology changed in 2021 (CAPI/CAWI mode shift). Pre-2021 and post-2021 data are not directly comparable without adjustment.
- **Wage data** — the ZUS administrative data covers the formal sector only; GUS survey data covers enterprises with 10+ employees. Neither captures the full economy.

**Rule:** Always note the data vintage and any known revisions. A result based on preliminary data may not hold after revision.

### 4.2 Structural Breaks

Polish economic time series are affected by several structural breaks that must be accounted for in any longitudinal analysis:

| Break | Year | Effect |
|-------|------|--------|
| Currency redenomination | 1995 | Old złoty → new złoty (10,000:1). All nominal series before 1995 must be converted. |
| EU accession | 2004 | Structural convergence, fund inflows, trade liberalisation. Pre/post comparison requires controls. |
| Financial crisis | 2008–09 | Poland was the only EU country to avoid recession, but growth slowed sharply. |
| ESA 2010 transition | 2014 | National accounts methodology change. GDP levels revised upward ~5%. |
| BAEL methodology change | 2021 | LFS data collection mode changed. Employment and unemployment levels not comparable pre/post. |
| COVID-19 | 2020–21 | Massive shock to labour market, GDP, public finances. Any series spanning this period requires special treatment. |
| Inflation surge | 2022–23 | CPI peaked at 18.4% in February 2023. Nominal vs. real distinction critical for this period. |

**Rule:** Any analysis spanning a structural break must either: (a) use break dummies, (b) estimate separate models for each period, or (c) explicitly acknowledge the break and its potential effect on results.

### 4.3 Administrative vs. Survey Data

Poland has two parallel data systems that often produce different numbers for the same concept:

| Concept | Administrative source | Survey source | Difference |
|---------|---------------------|---------------|------------|
| Unemployment | PUP registration (registered unemployment) | BAEL (LFS, ILO definition) | Registered is typically 2–3x higher; different definitions |
| Employment | ZUS contributions (formal sector) | BAEL (LFS, total employment) | ZUS misses informal sector, self-employed, agricultural |
| Wages | ZUS (gross contributions) | GUS enterprise survey (10+ employees) | ZUS is administrative universe; GUS is sample of larger firms |
| GDP | National accounts (ESA) | — | Single source, but subject to revision |

**Rule:** Never mix administrative and survey series for the same concept without explicitly noting the definitional difference. Do not compare registered unemployment trends with BAEL unemployment levels.

## 5. Interpretation & Reporting

### 5.1 Coefficient Interpretation

| Model type | Coefficient means | Example |
|-----------|------------------|---------|
| **Level-level (OLS)** | 1-unit change in X → β-unit change in Y | β = 0.5: 1 pp increase in education → 0.5 pp increase in wages |
| **Log-level** | 1-unit change in X → 100×β% change in Y | β = 0.08: 1 additional year of education → 8% higher wages |
| **Level-log** | 1% change in X → β/100-unit change in Y | β = 0.5: 1% increase in GDP → 0.005-unit increase in employment rate |
| **Log-log** | 1% change in X → β% change in Y (elasticity) | β = 0.3: 1% increase in price → 0.3% decrease in demand |
| **Difference-in-differences** | Treatment effect: difference in differences | β = −2.1: treatment reduced unemployment by 2.1 pp relative to control |

**Rules:**
- **Always state the units** — a coefficient without units is meaningless.
- **Always state the reference category** for dummy variables.
- **For log models, use the exact transformation** (exp(β) − 1) for large coefficients, not the approximation (100×β%).
- **Report confidence intervals, not just p-values** — a coefficient of 0.5 with CI [0.1, 0.9] is more informative than "p < 0.05".

### 5.2 What Not to Claim

| Claim | When it is valid | When it is not |
|-------|-----------------|---------------|
| "X causes Y" | Randomised experiment, valid IV, DiD with parallel trends | OLS on observational data |
| "X is the main driver of Y" | Decomposition analysis, dominance analysis | Single regression coefficient |
| "The effect is large/small" | Compared to a meaningful benchmark (SD, policy threshold, prior literature) | Without any reference point |
| "The relationship is robust" | Tested across multiple specifications and samples | Tested in only one specification |
| "This proves" | Never in observational research | Always — use "suggests", "is consistent with", "is associated with" |

## 6. Common Errors in Applied Econometrics

### 6.1 P1-Level Errors (Invalid Results)

- **Endogeneity ignored** — OLS on a relationship where reverse causality or omitted variable bias is obvious (e.g., wages on education without controlling for ability)
- **Wrong standard errors** — non-robust SEs on cross-sectional data, non-clustered SEs on panel data, non-HAC SEs on time series
- **Spurious regression** — running OLS on non-stationary time series without cointegration test
- **Sample selection bias** — analyzing only observed outcomes without addressing selection (e.g., wages only for employed individuals)
- **Data leakage** — using post-treatment variables as controls, or using future information to predict past outcomes

### 6.2 P2-Level Errors (Questionable Results)

- **Overfitting** — too many controls relative to observations; rule of thumb: at least 10 observations per parameter
- **Functional form misspecification** — linear model for a clearly non-linear relationship without testing
- **Ignoring structural breaks** — estimating a single model across a period with known breaks
- **Cherry-picked time windows** — selecting start/end dates to maximise significance
- **Multiple testing without correction** — running 20 regressions and reporting the 2 significant ones
- **Weak instruments** — first-stage F-statistic below 10, not reported

### 6.3 P3-Level Errors (Noted Improvements)

- **No power analysis** — small sample, no discussion of minimum detectable effect
- **No robustness checks** — single specification reported
- **No discussion of limitations** — every model has limitations; acknowledging them is a strength
- **Missing data not addressed** — listwise deletion without checking whether missingness is random
- **No out-of-sample validation** — model fit reported only on training data
